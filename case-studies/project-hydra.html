PROJECT 02 · CYBERSECURITY & INFRASTRUCTURE

Project Hydra

A hands-on IT and cybersecurity home lab built progressively across five phases, covering hardware diagnosis, operating system deployment, server configuration, remote administration, virtualisation and network segmentation.

Hardware Troubleshooting Linux Ubuntu Server Kali Linux Samba SSH VirtualBox pfSense Network Segmentation

Project Overview

Project Hydra was developed as a practical home laboratory to build hands-on experience across IT infrastructure and cybersecurity.

The project began with four non-working computers and progressively developed into a functional environment containing Linux systems, a file server, remote administration capabilities and an isolated virtual cybersecurity network.

Each phase built on the previous phase, moving from foundational hardware and operating-system knowledge toward infrastructure and security lab capabilities.

Phase 01 — Hardware Diagnosis & Troubleshooting

Objective

Diagnose and identify the hardware issues affecting four non-working computers and restore usable hardware where practical.

Work Performed

  • Used a SystemRescue USB to boot the systems.
  • Performed CPU and hard-drive diagnostic testing.
  • Physically inspected components including RAM and hard-drive connections.
  • Compared symptoms and diagnostic results across the four systems.

Outcome

The investigation identified multiple hardware failures across the systems, including failed storage and a failed CPU. The desktop was successfully repaired by installing a 1TB SSD and two new RAM sticks.

Phase 02 — Operating System Installation & Configuration

Objective

Deploy dedicated operating systems on two repaired laptops and configure them for specific roles within the home lab.

Work Performed

  • Created bootable USB installation media.
  • Installed Kali Linux on the HP Pavilion for cybersecurity projects.
  • Installed Ubuntu Server on the Toshiba Satellite for server functionality.
  • Troubleshot and resolved installation issues during deployment.

Outcome

Both systems were successfully deployed and configured. The HP Pavilion became the Kali Linux cybersecurity workstation, while the Toshiba Satellite became the Ubuntu Server platform for subsequent lab development.

Phase 03 — File Server & Help Desk Implementation

Objective

Transform the Toshiba Satellite into a functional file server and centralise shared resources within the home network.

Work Performed

  • Installed and configured Samba on Ubuntu Server.
  • Created a dedicated shared folder.
  • Configured the Samba share through smb.conf.
  • Created server user accounts.
  • Configured permissions for access to the shared resources.
  • Connected two other laptops to the shared server.

Outcome

The Toshiba Satellite was successfully configured as a centrally managed file server. The environment provided practical experience with Linux administration, service configuration, configuration files and user permissions.

Phase 04 — Remote Administration & Access

Objective

Demonstrate the ability to remotely manage the Ubuntu server from another machine without requiring physical access to the server.

Work Performed

  • Used SSH from the Kali Linux laptop.
  • Established a remote connection to the Ubuntu server.
  • Practised executing commands remotely.
  • Managed files without a physical keyboard or monitor attached to the server.

Outcome

The Ubuntu server could be administered remotely from the Kali Linux workstation, demonstrating practical experience with remote Linux administration and SSH-based access.

Phase 05 — Virtualisation & Network Segmentation

Objective

Build an isolated virtual cybersecurity environment that could be used to safely practise offensive and defensive security techniques without placing the wider network at risk.

Work Performed

  • Installed and configured VirtualBox as the hypervisor.
  • Deployed pfSense as a virtual firewall.
  • Configured pfSense to provide a separate lab network.
  • Created a Kali Linux virtual machine for security testing.
  • Created a Metasploitable virtual machine as an intentionally vulnerable target.
  • Created an Ubuntu desktop virtual machine representing a normal user system.

Outcome

A functional isolated virtual lab was successfully built. The environment provides a controlled network in which security techniques and vulnerabilities can be studied without directly exposing the live network.

Lab Architecture

The completed environment progressed from physical systems into a virtualised security laboratory. The final phase introduced distinct virtual roles for the firewall, attacker, vulnerable target and user workstation.

  • Virtualisation Host: Ubuntu Server desktop environment
  • Firewall: pfSense
  • Attacker: Kali Linux
  • Target: Metasploitable
  • User System: Ubuntu Desktop
