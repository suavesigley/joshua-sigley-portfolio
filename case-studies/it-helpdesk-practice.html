PROJECT 03 · IT OPERATIONS

IT Support & Active Directory Practice

A hands-on IT support portfolio documenting ticket resolution, Active Directory administration, access management, remote troubleshooting and infrastructure support using a simulated Service Desk environment.

Active Directory IT Support Access Management Remote Support Troubleshooting Ticket Documentation

Overview

This project was developed to build practical, documentable experience aligned with Tier 1 Help Desk, Service Desk and junior IT support responsibilities.

The portfolio uses the ServiceDesk Simulator to work through realistic support requests and documents the investigation, actions taken, resolution and skills demonstrated for each ticket.

The work also provides a foundation for cybersecurity operations by demonstrating how identity, access, endpoint and infrastructure issues are handled at the operational level.

Objectives

  • Practise structured IT support ticket handling.
  • Develop practical Active Directory user and group administration skills.
  • Apply least-privilege principles to access changes.
  • Practise joiner and mover access-management workflows.
  • Develop a methodical troubleshooting process.
  • Practise remote support and endpoint troubleshooting.
  • Develop experience handling higher-priority infrastructure incidents.
  • Maintain clear and auditable ticket documentation.

Environment

The project was completed using the ServiceDesk Simulator as the practice environment.

Documented Support Work

01 — Legal Name Change

A low-priority account update requiring an employee's display name and primary email address to be changed following an HR-approved legal name change.

The previous email address was retained as an alias so that messages sent to the former address would continue to reach the user.

This demonstrated directory user management, email configuration, identity-change handling and auditable ticket closure.

02 — New Hire Account Setup

A new employee account was created in Directory and provisioned for an Engineering role.

Required security groups included Engineering, VPN-Users and CodeRepo-Access. The completed account and group memberships were verified before the ticket was closed.

This demonstrates account provisioning, group-based access control, onboarding procedures and accurate documentation.

03 — Department Transfer Access

An employee transferring from Engineering to IT Infrastructure required their existing access to be modified to match the new role.

Engineering group membership was removed and IT Infrastructure access was granted. The final group membership was verified to ensure the account retained only the required access.

This is particularly relevant to security operations because it demonstrates least privilege, access revocation and the mover component of the joiner-mover-leaver lifecycle.

04 — Second Monitor No Signal

A user's second monitor was displaying "No Signal" and was no longer functioning correctly. The monitor had already been tested on another workstation, helping narrow the problem away from the display hardware.

A remote support session was initiated. The workstation displayed abnormal colour behaviour, after which installed drivers and firmware were reviewed and confirmed to be current.

The workstation was remotely restarted. Following the restart, the display returned to normal operation and dual-monitor functionality was restored.

This demonstrates remote support, methodical fault isolation, driver and firmware verification and structured troubleshooting.

05 — All Printers Offline

A high-priority infrastructure incident affected printing across the office. Multiple users were unable to print, creating significant business impact.

Investigation moved beyond individual endpoints to the underlying infrastructure. The print server, PRINT01, was identified in a degraded state with elevated CPU and memory utilisation.

PRINT01 was rebooted and monitored through the restart. Once the server returned to an online state, printing services were restored across the office and the affected user confirmed normal operation.

This demonstrates incident prioritisation, infrastructure troubleshooting, server-level diagnosis, service restoration and communication during a business-impacting outage.

Security Operations Relevance

Although this project is primarily focused on IT support, several of the demonstrated workflows directly overlap with security operations.

Identity and access management is a core security function. Creating accounts, assigning group memberships, removing obsolete access and validating permissions are all operational controls that reduce unnecessary access.

The department-transfer ticket particularly demonstrates this principle by removing the user's previous Engineering access before confirming the new IT Infrastructure permissions.

The project also demonstrates the importance of understanding normal endpoint and infrastructure behaviour. This foundation is useful when investigating abnormal authentication activity, endpoint issues or infrastructure-related security events in a SOC environment.

  • High-priority infrastructure incident investigated and resolved.
